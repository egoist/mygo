# Languages

An app shows a locale: the language of the strings MyGo writes itself, and
the one an app asks about to write its own. It follows the user's preferred
locale by default, `App.SetLocale` changes it while the app runs, and an app
can remember the language its user picked for the next run.

An app's own strings are its own: MyGo matches locales and says what its
own controls say, it does not hold an app's texts.

## The locale an app shows

`App.Locale` returns the locale the app shows as a language tag, such as
`en-US` or `zh-Hant-HK`. `App.SetLocale` makes a tag that locale, and an
empty tag follows the user's preferred locale again:

```go
mygo.App.Locale()          // "en-US"
mygo.App.SetLocale("zh-Hans")
mygo.App.SetLocale("")     // follow the system again
```

Both the controls of the native UI and the app follow it at once: the
calendar of a date picker says its month names in Chinese after
`SetLocale("zh-Hans")`, without restarting the app or reopening the window.
It is safe from any goroutine.

`App.OnLocaleChanged` tells an app that it changed, in time to rebuild what
it shows; the call comes on the main thread, and it is also where an app
with its own strings picks the language it writes them in:

```go
mygo.App.OnLocaleChanged(func(locale string) {
	win.Update(func() { view.lang = locale })
})
```

A language menu is a menu of the languages the app has, each setting its
tag:

```go
ui.MenuButton(c, "Language", func(m *ui.Menu) {
	for _, l := range []struct{ tag, name string }{
		{"", "Follow the system"},
		{"en", "English"},
		{"zh-Hans", "简体中文"},
		{"zh-Hant", "繁體中文"},
	} {
		if m.Item(l.name).Chosen() {
			mygo.App.SetLocale(l.tag)
		}
	}
})
```

Pages of a web frontend hear it as well. The bridge a page runs on carries
the tag as `mygo.locale`, which is the locale at the moment the page starts,
and the app tells every open page when it changes, with the new tag:

```ts
mygo.locale                      // "zh-Hans"
mygo.on("mygo:locale", (tag) => { … })
```

[`mygo-runtime`](frontend.md) wraps both: `locale()` returns the tag the app
shows now, and `onLocaleChange` subscribes to it. A page loaded later, by a
reload or a navigation, hears the current locale as it loads, and a window
created before the change is not stuck with the tag it started with.

The texts of a frontend stay the frontend's own business: keep them in its
own i18n and pick the language with the tag it hears, as an app picks its
strings with `App.OnLocaleChanged`. macOS and Windows report a change of the
system's language while the app runs, and an app following the system follows
it; Linux does not report it, and `App.SetLocale` is how the language changes
there.

## Remembering the language

An app can keep the language a user picked, so that the next run starts with
it instead of the one the system prefers. `App.RememberLocale(true)` turns it
on, and it is off by default:

```go
func main() {
	mygo.App.RememberLocale(true)
	// …
	if err := mygo.App.Run(); err != nil {
		log.Fatal(err)
	}
}
```

From then on `App.SetLocale` saves the tag in `locale` in
`App.Path(mygo.PathUserData)`, the per-user directory that also holds
`window-state.json`; `SetLocale("")` removes it and follows the system again,
and `Run` reads it back before anything shows. The app therefore starts with
the language its user picked, and the system's own language does not override
it while the app shows one of its own.

The file is one line, a language tag, so an app can read it, write it or
delete it itself; a file that is empty, damaged or holds no language tag is
ignored, and the next `SetLocale` replaces it. A tag set before
`RememberLocale(true)` is saved right away, so both orders work:

```go
mygo.App.SetLocale("zh-Hans")
mygo.App.RememberLocale(true)
```

A build for the browser keeps no file and `RememberLocale` does nothing
there: the page owns the language of its windows.

## Matching a locale

The desktop reports a locale in whatever form it likes: `en-US`,
`zh_Hant_TW.UTF-8`, `sr_RS@latin`. `i18n.Match` picks the language an app
has that best suits it:

```go
i18n.Match("zh-TW", []string{"en", "zh-Hans", "zh-Hant"}) // "zh-Hant"
i18n.Match("pt-PT", []string{"en", "pt-BR"})              // "pt-BR"
i18n.Match("es-419", []string{"en", "es-ES"})             // "" (Spanish of Spain is not Latin American Spanish)
```

It tries the same language, script and region, then the same language and
script, then the same language and region, then the language, then another
variant of the language, as `pt-PT` gets `pt-BR`. It returns `""` when
nothing suits, and the app falls back to the language it writes its own
strings in. Two scripts of Chinese are not variants of each other: `zh-TW`
does not match `zh-Hans`, and Chinese with no script is Simplified, except
in Taiwan, Hong Kong and Macao.

`i18n.BaseLanguage` returns the language of a tag (`zh-Hant` is `zh`).

## The strings of the controls

The controls that say something of their own say it in the language of the
locale the app shows: MyGo has those strings in English, Simplified and
Traditional Chinese. A locale of another language leaves them in English.
They are the strings of the calendar and the date picker (the month and the
year it shows, the weekday initials, the buttons, the day labels assistive
technology reads, the day its week starts on), of the menu a text field
shows (Undo, Cut, Copy, Paste, Delete, Select All), of the find bar and the
search field, of the buttons that clear a search and remove a token, of the
color picker, of the split view's divider, of the inspector and of a
toolbar's More button.

The code editor (package `ui/editor`) says its own through the same texts:
the menu of a code editor (Cut, Copy, Paste, Select All, Toggle Comment, Go
to Definition, the Selection, Transform and Folding submenus), its find bar
(Find, Replace, Replace All, Match case, Match whole word, Use regular
expression, Find in selection, Previous match, Next match, Close, the count
of matches, Invalid, No results), its go to line bar and its completion
list, and its diff view, which says how many unmodified lines are hidden,
Revert and Keep, Expand up, down and all, Line 12, New text and Old text.

A package built on the controls reads the texts of the app's locale with
`Context.Texts`, and says them where it builds its own elements, as the code
editor does.

`ui.UseTexts` changes what a language says, or adds a language the
framework has none of. A field a change leaves at its zero value keeps what
the language says, so a change says only what it changes:

```go
ui.UseTexts(map[string]ui.Texts{
	"zh-Hans": {NextMonth: "下一月"},
	"de":      {Find: "Suchen", Search: "Suchen", Clear: "Löschen"},
})
```

`ui.Texts` holds what a language needs beyond plain strings too: the
initials of its weekdays, `ui.Weekday(time.Sunday)` for a week that starts
on Sunday, and the functions that write a month and a year, a day, a count
of matches, the range of lines a go to line bar takes and the line a diff
view's gutter adds. A language added takes English for what it leaves out.
It is safe from any goroutine, and the windows shown draw their controls
again with the texts it set. One change covers the code editor too, which
reads the same texts.

## The strings of an app

The recommended shape is one Go value per language, with a field per
string, so that the compiler refuses a language that misses one:

```go
type strings struct {
	Title    string
	Deleted  func(n int) string
}

var translations = map[string]strings{
	"en": {
		Title:   "Notes",
		Deleted: func(n int) string { return fmt.Sprintf("Deleted %d notes", n) },
	},
	"zh-Hans": {
		Title:   "笔记",
		Deleted: func(n int) string { return fmt.Sprintf("已删除 %d 条笔记", n) },
	},
}
```

Pick the language from `App.Locale` with `i18n.Match`, keep a fallback for
when nothing matches, and read the strings where they are shown rather than
storing them: the locale can change at any time.

```go
func (a *app) texts() *strings {
	lang := i18n.Match(mygo.App.Locale(), slices.Collect(maps.Keys(translations)))
	if s, ok := translations[lang]; ok {
		return &s
	}
	s := translations["en"]
	return &s
}
```

The updater plugin works this way, and its `Options.Strings` shows an app
adding languages to a plugin's own window.

`i18n.Catalog` holds those values for an app that would rather not match
locales itself: `i18n.New("en", translations)` gives a catalog whose `Get`
takes a locale, whose `Languages` lists what it has, and whose `Use` adds a
language while the app runs, as `ui.UseTexts` does for the controls.

A string with a count in it is often the whole of such a function: a
language's plural forms and its numbers are what `i18n.Select` writes, as
below.

## Plurals, numbers and dates

`i18n` writes a count with the form the language uses, and a number or a
date the way the language writes it, for `i18n.Languages()`: seventeen
languages, from English to Arabic, with no dependency and no data file.

```go
var files = map[string]i18n.Forms{
	"en": {One: "%d file", Other: "%d files"},
	"zh-Hans": {Other: "%d 个文件"},
	"ru": {
		One:   "%d файл",
		Few:   "%d файла",
		Many:  "%d файлов",
		Other: "%d файла",
	},
}

i18n.Select(locale, n, files[lang]) // "1 file", "3 файла", "5 файлов"
```

The forms are the six plural categories Unicode CLDR names, `Zero`, `One`,
`Two`, `Few`, `Many` and `Other`. A language that does not use one leaves it
empty, and `Select` falls back to `Other`, then to `One`, so an app fills in
only what its languages use. An app that writes its own words asks for the
category itself:

```go
switch i18n.PluralOf(locale, n) {
case i18n.One:
	return fmt.Sprintf("%d файл", n)
case i18n.Few:
	return fmt.Sprintf("%d файла", n)
default:
	return fmt.Sprintf("%d файлов", n)
}
```

`i18n.Number` writes a number of any numeric type the way the language
writes numbers — its separators, its groups of digits and its own digits:
`i18n.Number("en", 1234567)` is "1,234,567", `i18n.Number("de", 1234567)`
is "1.234.567", `i18n.Number("hi", 1234567)` is "12,34,567" (Hindi groups
by two after the first group of three) and `i18n.Number("ar", 1234)` is
"١٬٢٣٤". `Select` writes the count it puts in the form with it, so a
Russian "5 файлов" holds "5" and an Arabic count holds "٥".

`i18n.Date` writes a date in one of three styles, `i18n.Short`,
`i18n.Medium` and `i18n.Long`, and `i18n.Time` writes the time of day with
the clock and the words for the morning the language uses:

```go
t := time.Date(2026, time.March, 5, 17, 4, 0, 0, time.Local)
i18n.Date(locale, t, i18n.Long)   // "Thursday, March 5, 2026", "2026年3月5日星期四"
i18n.Date(locale, t, i18n.Medium) // "Mar 5, 2026", "5 mars 2026", "5 марта 2026 г."
i18n.Date(locale, t, i18n.Short)  // "3/5/26", "05.03.26", "2026/03/05"
i18n.Time(locale, t)              // "5:04 PM", "17:04", "下午5:04", "٥:٠٤ م"
```

A language `i18n` has no data for is written as English numbers, an ISO date
("2006-01-02") and the 24 hour clock, never as something wrong. The data is
Go tables inside the package, so it costs no build step and works the same
on every platform and in a browser build; adding a language is a table.

The controls of the native UI write their own counts and their own dates
with the language the app shows, so an app that only reads `ui` needs none
of this. These helpers are for an app's own strings.

## The languages a build declares

The strings of the controls are what the app says; what the *system* says
of the app — its name in the Finder, in a Linux launcher and in the file
properties of Windows, and the languages of its installer — comes from
[`languages`](configuration.md#languages) in the configuration, which
`mygo build` writes into the app of each platform:

```json
{
  "name": "Notes",
  "languages": [
    {"tag": "en"},
    {"tag": "zh-Hans", "name": "笔记", "comment": "随手记笔记", "keywords": ["笔记", "记事本"]}
  ]
}
```

macOS gets `CFBundleDevelopmentRegion`, the first tag, `CFBundleLocalizations`,
and a `zh-Hans.lproj/InfoPlist.strings` naming the app in each language that
names it differently: the Finder, the menu bar and the system's own dialogs
of the app say it. Linux gets `Name[zh_Hans]`, `Comment[zh_Hans]` and
`Keywords[zh_Hans]` in its desktop entry. The Windows installer offers each
language to a system of that language, and the file properties of the app
hold one string table per language, which Windows shows in the language of
the system. A language Windows or NSIS does not know is skipped, with a
warning, and the app keeps the languages it has.

A build declaring languages is separate from the app showing a locale: the
first is what the system reads of the app before it runs, the second is what
the app says while it runs.
