# 语言

MyGo 应用可以用用户的语言显示文本。文本保存在消息目录中，每种语言对应一个 JSON 文件，`mygo dev` 和 `mygo build` 据此生成 Go 包，为每条消息提供带类型的函数，按应用当前语言返回文本，并处理该语言的复数规则。应用自身的文本、MyGo 的控件和菜单，以及 Web 页面（如果有），都使用同一种语言。

```json
{
  "filesSelected": "{count, plural, =0 {No files selected} one {# file selected} other {# files selected}}"
}
```

```go
ui.Text(c, locales.FilesSelected(len(app.selected))) // "3 files selected"
```

底层的 [`i18n`](#包-i18n) 包用 Unicode CLDR 的数据格式化数字和日期，
有前端的应用还能以 TypeScript 模块得到同样的消息（[在页面中](#在页面中)）。

## 消息目录

在[配置](configuration.md#i18n)中启用消息目录，写在
`mygo.json`（或 `mygo.config.ts`）里：

```json
{
  "i18n": { "dir": "locales", "source": "en" }
}
```

`dir`（默认 `locales`）为每种语言保存一个消息目录，以其
[BCP 47](https://www.rfc-editor.org/info/bcp47) 标记命名：`en.json`、
`de.json`、`pt-BR.json`、`zh-Hans.json`、`zh-Hant.json`。`source`
（默认 `en`）是应用编写时所用的语言：它的消息目录包含每条消息，其他目录回退到它。
应用随附的语言就是 `dir` 中的文件；该目录除这些文件和 Go 文件外不放别的东西；
没有消息目录的应用随附英语。

消息目录是一个由消息组成的对象，采用 ARB 格式，由键来命名消息。源语言的消息目录还会在带 `@`
的键下描述这些消息，供译者和生成的代码使用：

```json
{
  "@@locale": "en",
  "filesSelected": "{count, plural, =0 {No files selected} one {# file selected} other {# files selected}}",
  "@filesSelected": {
    "description": "The status bar, while files are selected.",
    "placeholders": {
      "count": { "type": "int", "example": "3" }
    }
  },
  "greeting": "Hello, {name}!"
}
```

```json
{
  "@@locale": "de",
  "filesSelected": "{count, plural, =0 {Keine Dateien ausgewählt} one {# Datei ausgewählt} other {# Dateien ausgewählt}}",
  "greeting": "Hallo, {name}!"
}
```

键是一个字母，后面是字母、数字和 `_`；每个键对应的函数都以它命名。占位符的 `type` 是
`String`、`int`、`double`、`num`、`DateTime` 或 `Object`，它决定函数参数的类型
（Go 中为 `string`、`int`、`float64`、`float64`、`time.Time` 和 `any`；
TypeScript 中为 `string`、`number`、`Date` 和 `unknown`）。没有 `type` 时，
被 `plural`、`selectordinal` 或 `number` 计数的参数是 `int`，`date` 或 `time`
参数是 `DateTime`，其他任何参数是 `String`。参数先按 `placeholders` 的顺序排列，
再按消息中的顺序排列。`@@locale` 是可选的，必须指明文件的语言。

键是扁平的：键中的点留给 MyGo 自己的字符串
（[`mygo.undo`](#mygo-自己的字符串)）。用共同的开头命名相关的消息，如
`sidebarTitle`、`sidebarEmpty` 和 `sidebarNewNote`，它们会在消息目录和编辑器的
补全（`locales.Sidebar…`）中排在一起。

## 消息

消息用 ICU MessageFormat 编写，ARB 文件、Android 和 Format.JS 都用这种格式：

| 消息 | 含义 |
|---|---|
| `Hello, {name}!` | `name` 的值放在对应位置 |
| `{count, plural, one {# file} other {# files}}` | `count` 在消息语言中的复数类别对应的分支；`#` 是数字 |
| `{count, plural, =0 {No files} one {# file} other {# files}}` | `=0` 用于恰好 0，先于各复数类别 |
| `{n, plural, offset:1 =0 {Nobody} =1 {{host}} one {{host} and # other} other {{host} and # others}}` | 带 `offset:1` 时，复数类别和 `#` 按 `n - 1` 计数 |
| `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` | 序数类别的分支：1st、22nd、103rd、11th |
| `{gender, select, female {She} male {He} other {They}} replied.` | 按值命名的分支，否则 `other` |
| `{price, number}`, `{ratio, number, percent}`, `{n, number, integer}` | 以该语言的方式写出的数字（1,234.5；1.234,5；12,34,567） |
| `{price, number, ::.00}`, `{n, number, ::group-off}` | 恰好两位小数、或没有千位分隔符的数字 |
| `{price, number, ::currency/EUR}` | 以该语言的方式写出的欧元金额（€1,842.00；1.842,00 €） |
| `{day, date, short}`, `{day, time, short}` | 按样式写出的日期或时间：`short`、`medium`、`long` 或 `full` |
| `{day, date, ::yMMMd}` | 按 CLDR 骨架中字段写出的日期，采用该语言的顺序（Jan 5, 2026；5. Jan. 2026） |

分支可以嵌套，每个 `plural`、`selectordinal` 和 `select` 都有一个
`other` 分支。`{n}` 中的数字按 `{n, number}` 的写法写出：最多三位小数，
带分组，用该语言的数字字符；以十进制字符串给出的数字 `"1.50"` 保留其小数位。
复数分支按 `#` 写出的数字来选，和 ICU 的选择一样：
1.0004 写作 1，它在英语中的分支是 `one`。`{t}` 中的时间按
`{t, date, short}` 与 `{t, time, short}` 合起来的方式写出。Go 中的数字和日期
遵循 CLDR 的数据，页面中遵循 `Intl`，两者一致（见
[格式化数字和日期](#格式化数字和日期)）。在 ICU 的数字骨架中，Go 和页面读取
`percent`、`integer`、小数位的精度（`.00`、`.0#`）、`group-off` 和
`currency/EUR`（带货币符号和小数位的金额）。复数类别是
[Unicode CLDR](https://cldr.unicode.org) 为该消息语言定义的那些：英语中为
`one` 和 `other`，中文和日语中只有 `other`，俄语中为 `one`、`few`、`many`
和 `other`，阿拉伯语中有六种。写出该语言具有的类别；`other` 是必需的。

撇号用于转义后面的花括号，或复数分支中的 `#`：`'{'` 表示 `{`，
`'{name}'` 表示 `{name}`，两个连续撇号表示一个撇号。其他位置的撇号按原样显示，
所以 `don't` 不需要加引号。

## 在 Go 中

`mygo dev`、`mygo build` 和 `mygo generate` 把 `catalog_gen.go` 写到消息目录
所在目录中，它是一个独立的 Go 包（以目录命名，或按该目录中其他 Go 文件声明的名称），
内嵌这些消息目录：

```go
import "example.com/notes/locales"

title := locales.FilesSelected(3)                // in the language the app shows
german := locales.In("de").FilesSelected(3)      // in another
```

每个键对应一个函数，参数类型由占位符决定，按应用当前语言返回消息；
另有 `locales.In(tag)` 上的方法，用于指定其他语言。无参数的消息格式化一次后会被缓存，
再次显示只需一次 map 查找，不分配内存：原生 UI 的视图每一帧都会显示它的消息。

这个包在初始化时把它的消息目录注册到 `i18n` 包，这使消息目录的语言成为应用的
语言：导入它；如果 Go 代码本身不显示任何消息，就用
`import _ "example.com/notes/locales"`。应用没有这样做时，`mygo dev` 和
`mygo build` 会警告。

`mygo dev` 在启动时写出这些函数，并在每次消息目录变化时再次写出，`mygo build`
在编译应用之前写出；`mygo generate` 只写出它们。它们是生成的代码：与消息目录
一起提交，这样 `go build` 和 `go test` 无需 CLI 也能工作。

### 语言变化时

原生 UI 的视图每一帧都会重新构建，因此它显示的内容会随语言变化：

```go
func (app *notes) view(c *ui.Context) {
	ui.Column(c).Gap(8).Children(func() {
		ui.Text(c, locales.FilesSelected(len(app.selected)))
		if ui.Button(c, locales.NewNote()).Clicked() {
			app.add()
		}
	})
}
```

按角色标注的菜单项（"Undo"、"Quit Notes"）会自己采用新语言的标签。应用只设置
一次的内容，例如窗口标题或它自己菜单项的标签，需要在收到语言变化通知时重新设置：

```go
win := mygo.NewWindow(mygo.WindowOptions{Title: locales.Title(), Content: ui.View(app.view)})
mygo.App.OnLocaleChanged(func(string) {
	win.SetTitle(locales.Title())
	mygo.App.SetMenu(app.menu()) // the menu, made again with locales' labels
})
```

## 应用显示的语言

应用只显示一种语言，由 `mygo.App.Locale()` 返回：在应用所包含的语言中，选择用户读得
最顺的那种，按系统列出的用户首选语言顺序（`App.PreferredLanguages()`），
例如 `zh-TW` 的读者会得到 `zh-Hant`；否则是应用的源语言。只用英语写成的应用
对中文读者也显示英语，MyGo 的控件和菜单也一样，正如 AppKit 所做。应用包含的
语言就是其消息目录的语言；没有消息目录的应用则用 `App.SetLanguages` 设置这些语言。

在 0.5 之前，`App.Locale()` 返回用户的第一首选语言，无论应用支持哪些语言。
自己翻译文本、既没有消息目录也不用 `App.SetLanguages` 的应用，现在会从中得到
`"en"`：用 `App.SetLanguages` 声明它的语言，或者从
`App.PreferredLanguages()` 读取用户的语言。

`App.SetLocale("de")` 立即改用另一种语言，并在之后的启动中保留它；
`App.SetLocale("")` 再次跟随用户的语言。`App.ChosenLocale()` 返回 `SetLocale`
选择并保留的值，已规范化（`"de"`、`"zh-Hans"`），或在应用跟随用户语言时为
`""`；仅凭 `App.Locale()` 返回的最终语言，无法判断应用是否跟随系统。下面是一个语言菜单，
其中一项跟随系统，每种语言用其母语名称（"Deutsch"、"简体中文"）：

```go
chosen := mygo.App.ChosenLocale()
items := []*mygo.MenuItem{{Label: "System", Type: mygo.MenuItemRadio,
	Checked: chosen == "",
	Click:   func(*mygo.MenuItem, *mygo.Window) { mygo.App.SetLocale("") }}}
for _, tag := range mygo.App.Languages() {
	items = append(items, &mygo.MenuItem{Label: i18n.Autonym(tag), Type: mygo.MenuItemRadio,
		Checked: chosen == tag,
		Click:   func(*mygo.MenuItem, *mygo.Window) { mygo.App.SetLocale(tag) }})
}
```

`ChosenLocale` 返回所选标记的规范化形式，即使应用并不支持该语言：
向 `SetLocale` 传入 `App.Languages()` 之外的标记（如 `"de-AT"`）后，仍会返回
该标记，便于与应用自己的语言标记比较，或用 `i18n.Match` 匹配。通过 `MYGO_LOCALE` 为本次运行
指定语言时，返回的是该语言。从非主线程的 goroutine 调用时，会等待主线程处理，
因此返回值会反映此前的 `SetLocale` 调用。

macOS 把语言作为应用的语言保存在系统设置中（应用默认设置中的
`AppleLanguages`），AppKit 和 WebKit 从下次启动起会用这种语言显示自己的文本；浏览器
把它保存在 `localStorage` 中；Windows 和 Linux 保存在
`App.Path(mygo.PathUserData)` 的 `locale` 文件里。`SetLocale` 改变语言或用户
语言发生变化时，`App.OnLocaleChanged` 都会收到通知（macOS、Windows 和浏览器
报告它们的语言；Linux 读取环境变量 `LANGUAGE`、`LC_ALL`、`LC_MESSAGES` 和
`LANG`，只读一次）。

语言变化时，原生 UI 的窗口重新绘制，按角色标注的菜单项会显示新语言的标签
（见[语言变化时](#语言变化时)），页面也会收到通知（[在页面中](#在页面中)）。
应用会按语言的方向布局，阿拉伯语和希伯来语为从右到左，除非 `MYGO_DIRECTION`
（`rtl` 或 `ltr`）另有说明：原生 UI、页面（`mygo.dir`）以及 Linux 上 GTK
自己的控件（如菜单）都一致。

### 原生 UI

`ui.Context.Locale()` 和 `ui.Context.Region()` 返回应用的语言和格式；帧会跟随
它们的变化。文本按应用的语言绘制，这决定了系统的文本栈会为它选用哪些字形，
就像中文和日文绘制同一个汉字时字形不同。`Element.Lang` 设置元素文本及其内部元素
的语言，如 HTML 的 `lang` 所做，`Span.Lang` 设置 `RichText` 中一个 `Span` 的
语言，`Font.Lang` 设置 `Painter` 排版的文本的语言：

```go
ui.Text(c, "「直」").Lang("ja") // a Japanese quote in a Chinese app
```

不使用汉字的语言中的汉字（如英语文本中的中文名字）保留系统为用户选择的字形，
如浏览器所做。在 Windows 上，字体回退依据用户区域格式的区域设置，当该区域设置
不使用这些汉字时，它们会采用用户首选语言中第一个使用这些汉字的语言：在首选语言
包含中文的英语 Windows 上，英语应用中的中文歌名用一种中文字体绘制，而不是
日文字体和中文字体两种字重的混合。浏览器按页面的语言绘制原生 UI 的文本，
MyGo 让页面语言成为应用的语言。

韩语文本（`ko`、`ko-KR` 等）按词换行，在空格处和标点之后断行，这符合韩语的书写方式，
也符合韩国网站用 CSS 的 `word-break: keep-all` 让浏览器换行的方式，而不是像
Unicode 的换行规则允许的那样在任意两个音节之间断开；比一行更长的词仍会在词内
断开，除非文本本来就要求保持单词完整（`TextShape.NoBreakWords`）。显示韩语的应用
（`App.SetLanguages("ko")`）在所有平台上于 `Text`、`TextInput`、`TextArea`
以及自行排版的文本中采用这种换行方式；其他语言的应用也可用 `Lang("ko")` 为其中
的韩语文本启用这种换行方式。

`examples/gallery` 有一个语言页面：语言菜单、每种语言的数字和日期、
中文的控件，以及伪区域设置。

### 区域格式

日期、时间和数字的写法是一项独立的设置：`App.Region()` 返回用户格式所用的区域设置，
它可能与应用显示的语言不同，还返回一周的第一天以及时间是 12 还是 24 小时制，
并包含用户在系统设置中做的更改。`App.OnRegionChanged` 会收到它们变化的通知。
系统未提供的信息（例如 libc 缺少数据，或浏览器不提供相关信息）会取自 CLDR 为该地区提供的
周与时间数据（`i18n.FirstWeekday`、`i18n.HourCycle`）。

`Region.FormatLocale(language)` 如 Apple 的 `Locale.current` 那样把两者合在
一起：英语配英国格式是 `en-GB-u-fw-mon-hc-h23`，配德国格式是
`en-DE-u-fw-mon-hc-h23`；用它格式化，就能按用户设置的方式用应用的语言写日期：

```go
formats := mygo.App.Region().FormatLocale(mygo.App.Locale())
label := i18n.FormatDate(formats, due, i18n.DateOptions{Date: i18n.MediumStyle})
```

MyGo 的日期和时间控件就是这样：[日历](ui/calendar.md)把该地区的一周第一天
作为每周的开始，[日期输入框](ui/date-input.md)显示该地区的数字日期，
[时间输入框](ui/time-input.md)显示该地区的小时周期，上午和下午使用窗口的语言。

## 格式化数字和日期

`i18n` 包按 ICU 和浏览器 `Intl` 的写法输出数字、日期和时间，使用 Unicode
CLDR 中其现代覆盖范围（104 种语言的 430 个区域设置：`en`、`en-GB`、
`de-CH`、`pt-BR`、`zh-Hant-HK`、`ar-EG`……）的数据。没有数据的区域设置，按已有的
最近区域设置格式化（`zh-TW` 按 `zh-Hant`，`en-AU` 按 `en-001`），
否则按英语。

```go
i18n.FormatNumber("de", 1234567.891, i18n.NumberOptions{})                 // 1.234.567,891
i18n.FormatNumber("hi", 1234567, i18n.NumberOptions{})                     // 12,34,567
i18n.FormatNumber("fa", 0.25, i18n.NumberOptions{Percent: true})           // ۲۵٪
i18n.FormatNumber("en", 1.5, i18n.NumberOptions{MinFractionDigits: 2})     // 1.50
i18n.FormatNumber("en", 1234, i18n.NumberOptions{SignDisplay: i18n.SignAlways}) // +1,234
i18n.FormatNumber("en", 0, i18n.NumberOptions{SignDisplay: i18n.SignExceptZero}) // 0
i18n.FormatNumber("en", 1234, i18n.NumberOptions{Notation: i18n.CompactShort}) // 1.2K
i18n.FormatNumber("fr", 1234, i18n.NumberOptions{Notation: i18n.CompactLong})  // 1,2 millier
usd := i18n.CurrencyOf("USD")
i18n.FormatNumber("en", 1842, i18n.NumberOptions{Currency: usd})                   // $1,842.00
i18n.FormatNumber("en", -1842, i18n.NumberOptions{Currency: usd, Accounting: true}) // ($1,842.00)
i18n.FormatNumber("de", 1842, i18n.NumberOptions{Currency: i18n.CurrencyOf("EUR")}) // 1.842,00 €
i18n.FormatNumber("ja", 1842, i18n.NumberOptions{Currency: i18n.CurrencyOf("JPY")}) // ￥1,842
i18n.FormatNumber("en", 1842, i18n.NumberOptions{Currency: usd, CurrencyDisplay: i18n.CurrencyName}) // 1,842.00 US dollars
i18n.FormatNumber("en", 4.2e6, i18n.NumberOptions{Currency: usd, Notation: i18n.CompactShort})       // $4.2M
i18n.FormatDate("en", t, i18n.DateOptions{Date: i18n.FullStyle})           // Monday, January 5, 2026
i18n.FormatDate("ja", t, i18n.DateOptions{Date: i18n.LongStyle, Time: i18n.ShortStyle}) // 2026年1月5日 13:07
i18n.FormatDate("ru", t, i18n.DateOptions{Skeleton: "yMMMM"})             // январь 2026 г.
i18n.FormatDate("en", t, i18n.DateOptions{Skeleton: "jm", HourCycle: 24}) // 13:07
i18n.FormatDateRange("en", start, end, i18n.DateOptions{Skeleton: "yMMMd"}) // Jan 5 – 9, 2026
```

- **数字**：该语言的分隔符和分组方式（例如印度的 12,34,567；西班牙语和波兰语从五位
  开始分组，因此四位数不加分隔符）、它的减号和百分号，以及它的数字系统的数字
  字符（波斯语和埃及阿拉伯语用阿拉伯-印度数字，孟加拉语用孟加拉数字；
  `-u-nu-latn` 指定使用拉丁数字）。小数位与 `Intl` 一样采用就近舍入，中点值向远离零的方向舍入，
  也可采用中点取偶数的规则（`HalfEven`）。`NumberFormatter` 可保存格式化器以供复用。
- **符号**：`SignDisplay` 是 `Intl` 的 `signDisplay`：`SignAuto`（默认）只写
  负数的减号；`SignNegative` 也一样，但负零前不写减号；`SignAlways` 在非负数
  前写加号；`SignExceptZero` 也写加号，但在舍入为零的数字前不写；`SignNever`
  两者都不写。加号放在该区域设置放减号的位置，在百分号前（土耳其语中为
  "+%25"）和货币符号前（"+$1,842.00"）；如果该区域设置的负数格式把减号放在货币符号之后，
  加号也放在符号之后（荷兰语中为 "€ +1.234,00"，瑞士德语中为 "CHF+1'234.00"），
  紧凑数字的加号也一样（"+1.2K"）。
- **紧凑数字**，如图表坐标轴的标注：`Notation: i18n.CompactShort` 在英语
  中把 1234 写成 "1.2K"，法语中写成 "1,2 k"，日语中写成 1.2万；
  `i18n.CompactLong` 写成 "1.2 thousand" 和 "1,2 millier"，与 `Intl` 的
  `notation: "compact"` 配合 `compactDisplay` 的写法一样：两位有效数字，或者
  整个数字有两位及以上时写出整个数字（12K、123K），除非选项给出小数位；写出内容的
  复数形式（"2 millions"）；以及该区域设置没有紧凑模式时的十进制模式（德语把千写成
  整数，12.345）。
- **金额**，例如价格、总额或余额的显示：`Currency: i18n.CurrencyOf("EUR")`
  （ISO 4217 的代码）按 `Intl` 的 `style: "currency"` 输出数字，采用该区域设置
  的金额模式，货币符号的位置以及它与数字之间的空格都由该模式决定（"$1,842.00"、
  "1.842,00 €"、"EUR 1,842.00"），小数位采用 CLDR `currencyData` 中该货币的
  （USD 两位，JPY 没有，BHD 三位），`MinFractionDigits`、`MaxFractionDigits`
  和 `Integer` 像 `Intl` 的选项一样覆盖它们。`CurrencyDisplay` 即
  `currencyDisplay`：符号（`CurrencySymbol`，默认；英国英语中为 "US$"）、
  `CurrencyNarrowSymbol`（"$"）、`CurrencyCode`（"USD"）或 `CurrencyName`
  （"1,842.00 US dollars"，用金额的复数形式）。`Accounting` 即
  `currencySign: "accounting"`：在该区域设置如此书写负金额的地方写
  "($1,842.00)"。配合 `Notation` 时，金额按 `Intl` 的写法紧凑（"$4.2M"；
  带名称时为 "4.2 million euros"）。
- **日期和时间**按样式（`FullStyle` 到 `ShortStyle`，如 `dateStyle` 和
  `timeStyle`）或按**骨架**，即要显示的字段（任意顺序：`yMMMd`、`MMMd`、
  `Ed`、`jm`）：像 ICU 的 `DateTimePatternGenerator` 那样，从 CLDR 中找出最适合
  它的该区域设置模式，所以 `Intl` 中的
  `{year: "numeric", month: "short", day: "numeric"}` 和这里的 `yMMMd` 输出
  相同结果。`j` 是该区域设置周期中的小时；`HourCycle`（或区域设置中的
  `-u-hc-h23`）使它成为 12 或 24 小时制。日期使用公历，时间使用其
  `time.Location`。`DateFormatter` 保留一个格式化器，`Pattern` 说明模式。
- **范围**，例如日期范围选择器的触发标签：`FormatDateRange`（或
  `DateFormatter.FormatRange`）把两者共有的写一次、不同的写两次，如 `Intl`
  的 `formatRange` 配合 CLDR 的区间格式："Jan 5 – 9, 2026"、
  "Jan 5 – Feb 9, 2026"、"10:00 – 11:30 AM"，或当两者在选项所写的字段上都没有
  差异时只写一个日期。结束时间按开始时间所在的时区写出。
- **名称**：某个 `Width` 中的 `Months`、`Weekdays` 和 `DayPeriods`，单独使用
  （日历的标题，"январь"）或在日期中（"января"）；`Autonym` 是语言用自身
  语言写出的名称，用于语言菜单（"Deutsch"、"简体中文"、"British English"）。
- **周与时钟**：某个区域设置所属地区的 `FirstWeekday` 和 `HourCycle`（或该语言最
  可能的地区）；`RegionFor` 返回两者。

### 相对时间

`FormatRelativeTime` 按 `Intl.RelativeTimeFormat` 的写法输出值和单位，用于
时间戳、提醒和活动流：

```go
i18n.FormatRelativeTime("en", -3, i18n.RelativeMinute, i18n.RelativeTimeOptions{}) // 3 minutes ago
i18n.FormatRelativeTime("zh", 1, i18n.RelativeDay, i18n.RelativeTimeOptions{Auto: true}) // 明天
i18n.FormatRelativeTime("fr", -2, i18n.RelativeDay, i18n.RelativeTimeOptions{Auto: true}) // avant-hier
i18n.FormatRelativeTime("en", -3, i18n.RelativeMinute, i18n.RelativeTimeOptions{Style: i18n.RelativeNarrow}) // 3m ago
```

单位从 `RelativeSecond` 到 `RelativeYear`，包括周、月和季度。零值选项使用完整
名称，并且总是包含数字；`RelativeShort` 和 `RelativeNarrow` 缩短单位名称。
`Auto` 在该区域设置有 “yesterday”、“tomorrow” 和 “now” 这类词的地方使用
它们，其他地方使用数字。和 ICU 一样，它会把偏移量舍入到百分位，再据此选择词语：
`1.001` 天可能会显示为 “tomorrow”。数字最多保留三位小数，中点值取偶数，并选取
舍入后数字的复数形式；负零表示过去。`NewRelativeTimeFormatter` 会保留区域设置
和选项，供重复、并发使用。未知的单位或样式以及非有限值会 panic。

调用者计算值并选择单位；月或年是日历单位，不是固定时长。格式化不读取时钟，
也不启动计时器。Web 前端可以直接使用 `Intl.RelativeTimeFormat`。Go 格式化器
使用 CLDR 自己的词语，包括 ICU 78 缺少的区域设置（`ht`、`el-polyton`），以及
`be-tarask` 对当前分钟和小时的短格式和窄格式词语，而 ICU 78 从 `be` 继承这些
词语。

### 格式化的数据

格式化只分配结果本身；格式化器和区域设置的数据只创建一次并保留。数据经过
压缩，首次使用时解压，耗时不到一毫秒。每个应用都会链接数字格式化及其数据，约
3 KB，因为 MyGo 自己的字符串也要格式化数字；日期格式化及其数据、语言的
名称，只有在应用格式化日期时才会链接进去，例如应用有自己的消息目录（`NewCatalog`，
由 `mygo generate` 生成）、调用了 `ParseMessage`、使用了格式化器，或有读取这些
数据的函数。
紧凑数字的模式只链接进引用了 `CompactShort` 或 `CompactLong` 的应用，范围的
模式只链接进格式化范围的应用；消息不会读取这两者（ICU 的 `compact-short` 骨架
被写成普通数字）。货币的模式和符号（6 KB 数据，连同代码约 40 KB）会链接进
调用 `CurrencyOf` 或拥有自己消息（消息目录、`ParseMessage`）的应用，后者的
骨架可能引用货币；货币名称约 300 KB，只会链接进引用了 `CurrencyName` 的应用
（消息不支持 ICU 的 `unit-width-full-name` 等骨架选项，遇到这些选项时仍输出货币符号）；
紧凑金额的模式（10 KB）只会链接进同时引用了紧凑记法的应用。相对时间及其模式只会链接
进调用 `FormatRelativeTime` 或 `NewRelativeTimeFormatter` 的应用。它是一个包，
而不是每种语言一个：用户的区域格式可以是任何区域设置的，无论应用随附哪些
语言。

与 ICU 的不同之处（`i18n/format_icu_test.go` 列出了测试跳过的每种情况）：
UTC 以外的时区写成相对 GMT 的偏移（`GMT+8`、`GMT+05:30`），而 ICU 会给某些
时区命名（"China Standard Time"）；日历始终是公历，而 ICU 对泰语或波斯语的
默认是另一种历法；时间在 CLDR 有窄不换行空格的地方写普通空格，如 V8 所做，但范围
会保留 CLDR 的细不换行空格和窄不换行空格，如 V8 的 `formatRange` 所做（Safari 的写空格）；
ICU 78（CLDR 48.0）缺少数据或数据较旧的少数区域设置（海地克里奥尔语、多调
希腊语）采用 CLDR 48.2 的数据；缅甸语货币名称也采用 CLDR 的规则（ICU 放在金额后，CLDR
放在金额前），黑山塞尔维亚语西里尔字母区域设置中的货币名称也一样（ICU 在此使用拉丁字母）。金额遵循
ICU 的特殊行为：CLDR 为某种货币在某个区域设置中指定的格式（德国英语中的欧元，
"€1,842.00"），会用于使用该格式的地区中其他货币的显示（`en-DE` 中为
"US$1,842.00"），与 ICU 保存货币符号格式的方式一致。货币的小数位采用 CLDR 数据，与 V8
（Chrome、Edge 和 WebView2）一致；JavaScriptCore（Safari、WKWebView 和
WebKitGTK）采用 ISO 4217 的，少数几种不同（COP、HUF、IDR、IQD、IRR、LAK
和 PKR 在 CLDR 中没有小数位，在 ISO 4217 中有两或三位）。带
`MinFractionDigits` 的紧凑金额保留最多三位小数，如 ECMA-402 和
JavaScriptCore 所采用（"$1.234K"）；V8 则保留到最小位数（"$1.23K"）。

## MyGo 自己的字符串

MyGo 的控件、它的代码编辑器、差异查看器、富文本编辑器和 Markdown 视图、终端
插件、它的文稿对话框、页面的 `alert`、`confirm` 和 `prompt` 按钮、文件对话框的
标题，以及它的菜单，都会显示自己的文字："Undo"、"Find"、"Next month"、
"Do you want to save the changes made to the document “Notes”?"、
"Quit Notes"，以及辅助功能读出的名称（"hours"、"Saturation and
brightness"）。它们使用应用显示的语言：在原生 UI 中，使用窗口的语言
（`ui.Context.Locale`）。只随附英语的应用对中文读者也用英语显示它们，如
AppKit 所做。同一种语言下再次显示只需一次 map 查找，不分配内存，所以控件
每一帧都会显示它们。

英语总是会被链接进来。其他语言的翻译——目前有日语（`ja`）、简体中文（`zh-Hans`）
和繁体中文（`zh-Hant`）——是各自的包，这样应用只携带它所随附语言的翻译。
`mygo generate` 为应用的消息目录生成的代码会按应用的语言导入它们：有
`zh-TW.json` 的应用得到 MyGo 的 `zh-Hant`。没有消息目录、用
`App.SetLanguages` 设置语言的应用自己导入它们：

```go
import _ "github.com/egoist/mygo/locales/zh-Hans"
```

应用随附了 MyGo 已翻译的语言却没有导入翻译时，启动时会被告知，并在该语言下
用英语显示 MyGo 的字符串。应用可以通过其消息目录中 `mygo.<key>` 的键修改 MyGo 的
字符串，或为这些字符串提供其他语言：

```json
{
  "mygo.undo": "Rückgängig",
  "mygo.menuQuitApp": "{app} beenden"
}
```

这些键、对应的消息和参数构成了 MyGo 的消息目录，
[internal/l10n/en.json](https://github.com/egoist/mygo/blob/main/internal/l10n/en.json)。
字符串的解析与应用自己的字符串一样：先应用的语言，再它回退到的语言，然后应用
的源语言，最后英语。原生 UI 的检查器是开发者的工具，保持英语。

Windows 安装程序的完成页使用 `mygo.desktopShortcut` 作为创建桌面快捷方式的
复选框的文本。构建时从应用的消息目录（包括源语言的）读取它，或使用 MyGo 对该
语言的翻译，回退到英语（见[分发](distribution.md#语言)）。

### 为 MyGo 添加语言

MyGo 自己的字符串是 `internal/l10n/en.json`，每种翻译是
`locales/<tag>/<tag>.json`。要把 MyGo 翻译成某种语言，添加包含 `en.json`
每个键的 `locales/<tag>/<tag>.json`（描述说明每个键显示在哪里），运行
`go generate ./internal/l10n`（它生成该翻译的包，并把它加入 `mygo generate`
为应用链接的语言），以及 `go test ./internal/l10n`（它按 `mygo generate`
检查应用消息目录的方式检查它：每种语言的每条消息，带有源语言的占位符和该语言
的复数分支）。`mygo.appName` 和 `mygo.appDescription` 是应用在某种语言中的
名称和描述，打包时会把它们写到系统列出应用的位置（见
[构建与分发](distribution.md#语言)）。

## 选择哪条消息

消息取消息目录中与所请求语言最匹配的语言里的那一条：`zh-TW` 用 `zh-Hant`，
`pt-AO` 用 `pt-PT`，`en-AU` 用 `en-GB`。该语言缺少这条消息时，会沿 CLDR 的父级
区域设置回退（`en-AU`、`en-001`、`en`；`zh-Hant-HK`、`zh-Hant`），然后回退到
源语言：缺少的翻译会显示源语言的消息，而不是什么都不显示。它的复数分支遵循消息
所用语言的规则；数字和日期则遵循所请求语言的惯例。

## 检查消息目录

`mygo generate` 和 `mygo build` 检查消息目录，`mygo i18n check` 也一样。
错误会让它们停止：

- 文件名不是规范标记，或其 `@@locale` 不同；
- 无法解析的消息；
- 翻译有而源语言没有的键，或 MyGo 没有对应消息的 `mygo.<key>` 键；
- 翻译有而源语言消息没有的参数，或以其类型不允许的方式使用（被 `plural`
  计数的 `String`）；
- 两个键的函数会同名。

警告不会阻止它们：翻译缺少的消息（这些消息会显示源语言的版本）；翻译省略的参数；
它的语言没有的复数分支（英语中的 `few`），或翻译中缺少的复数分支（俄语中的
`few`，会用 `other` 代替）；消息未使用的占位符。

## 试用一种语言

`mygo dev -lang de` 用德语运行应用，不改变已保存的语言设置。两个伪区域设置可以在任何
翻译出现之前测试布局，做法与 Android 相同：

- `en-XA` 会给源语言消息中的字母加上变音符号，让它们变长三分之一，并用方括号
  括起来，`[Šéļéçţ ƒîļéš one two]`：保持原样的文本不在消息目录中，被截断的文本
  说明空间太小，带多个方括号的句子由翻译无法重排的片段组成。
- `ar-XB` 从右到左显示每个词，并把应用从右到左布局：没有镜像的内容就会暴露
  出来。

## 在页面中

有前端的应用会在页面中显示同样的消息。在
[TypeScript 客户端](bindings.md#生成的客户端)旁，CLI 生成一个以消息
目录所在目录命名的模块，如 `src/locales.ts`，每个键对应一个带类型的函数；没有前端
的应用不会得到这个模块。

```ts
import { languages, messages, messagesIn } from "./locales";

heading.textContent = messages.filesSelected(3); // in the language the page shows
messagesIn("de").greeting("Ada");                 // "Hallo, Ada!"
```

模块包含每种语言的消息，`mygo-runtime/i18n` 用浏览器的 `Intl` 格式化它们，
所以页面和 Go 会显示相同的文字，使用相同的复数形式。消息会随前端一起打包，而不是在
运行时获取：首次绘制就是正确的语言，无需等待请求，在浏览器中打开的开发服务器页面
也一样。`messages` 会以当前的语言显示每条消息：应用的语言（MyGo 在页面脚本
运行前交给页面），否则是浏览器的语言。

`mygo.locale` 和 `mygo.dir` 在页面脚本运行之前就已存在。语言变化时，页面会
收到 `mygo:locale` 事件（`mygo-runtime` 的 `onLocaleChange`）：重新绘制页面。
之后加载的页面以新语言开始。Web 视图也为自己的文本采用该语言：WebView2 在
其环境创建时采用（它会保留该语言，更改要等到下次启动才显示），WebKitGTK 立即
生效，WKWebView 从下次启动起生效。

`mygo-runtime/i18n` 的 `formatMessage(locale, message, args)` 格式化你自己
的消息。

## 包 i18n

生成的代码建立在
[`i18n`](https://pkg.go.dev/github.com/egoist/mygo/i18n) 包上，应用可以直接
使用：`NewCatalog` 从任何 `fs.FS` 读取消息目录，`ParseMessage` 和
`Message.Format` 格式化消息，`PluralCategory` 和 `OrdinalCategory` 给出数字
的 CLDR 复数类别（数字可以写作整数、浮点数或小数位有意义的十进制字符串，
`"1.50"` 有两位），`Parent` 给出区域设置回退到的区域设置；此外还有
[数字和日期](#格式化数字和日期)的格式化。它的数据来自 CLDR
`i18n.CLDRVersion`。
